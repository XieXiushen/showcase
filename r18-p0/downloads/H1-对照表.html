  1. 本次请求（每行同口径）：1069 prompt tokens、230 输出 tokens、-c 8192；prompt tok/s 为 cache_prompt=false 全量重算读数。
  2. 显存口径：整卡 nvidia-smi used，含桌面约 1331 MiB。「待机」＝模型加载完成后、发起请求前；「峰值」＝本次请求期间最大值。
  3. 首 token 三口径分开报、不混用：「冷」＝本次 server 进程的第一次多模态调用；「热·全量」＝同进程后续调用且 cache_prompt=false 全量重算；「缓存命中」＝同进程、相同 prompt、KV 前缀复用（服务端只算 1 个 token）。原文未给 G2/G3/G5 的冷启动读数，故写「未测」。
  4. 精度判据：make_test_image.py 真值逐字比对——gps_lat 128,430/0.42%/17、gps_lon 128,430/0.38%/9、road_name 128,430/6.71%/132、speed_limit 96,215/12.05%/48 四项全中；结论句原样输出（含「6.71%」「P2」「7 日内回补」）。六组回答逐字一致——FA、KV 量化、mmproj 位置乃至 CPU 退化都没有改变输出。
  5. decode 为两次读数，本表取首跑：G2 116.71（次跑 115.87）、G3 113.57（次跑 111.81）、G4 116.71（次跑 118.07）、G5 117.93（次跑 115.19）；G1 117.33、G6 12.70 为单次读数。
  6. 单位归一说明（不改数值）：「缓存命中」秒数在原文中写作 0.030 s（G1）、0.032（G2）、0.031（G3）、0.031（G4）、0.054（G5），本表统一补单位 s，数值逐字未改。
  7. G6 判据：启动目录同级没有 ggml-cuda.dll / cublas64_13.dll（只在子目录 cuda_v13\ 下）；进程正常、/health 正常 ok、日志无 CUDA offload 行也无报错，GPU 占用全程恒 1329–1342 MiB。此场景下 mmproj 同样无法上卡。
一句话结论：同一张 12GB 显卡、同一张图，把 mmproj 放回 GPU：prompt 80.07 → 2322.94 tok/s、热·全量首 token 13.37 s → 0.481 s、冷启动 12.97 s → 0.586 s，代价是显存 6273 → 8268 MiB（峰值 8369），全程无 OOM。G6 提醒：进程正常不等于 GPU 在跑——显存只占 1.3 GB 就是模型在 CPU 上（decode 12.70 vs 117.33，慢 9.2 倍）。
本文所有性能数字均为单机实测：RTX 5070 12GB（12227 MiB）／i5-14600K／32GB 内存／Windows 10，同一张测试图与同一 prompt；结论不迁移到其他硬件，你的读数以自己机器为准。
